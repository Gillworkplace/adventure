# VELA Adventure 策略优化 — 第一期研究结果

**研究日期：** 2026年9月8日（KST）  
**环境：** `adventure-1acaa72-v1`  
**选定策略：** `VELA-DP4-Expectimax-v1`  
**目标：** 平均最终 score 达到 1860 以上，挑战目标 1880 以上

## 1. 结论

完成了规则审计、独立参照实现验证、多个价值模型与搜索策略的实现、候选选择，以及固定策略的独立 100,000 局评估。

选定策略的最终平均分为 **1857.11013 分**，样本标准差为 **202.73817**，标准误为 **0.64111**。正态近似双侧 95% 置信区间为 **[1855.85355, 1858.36671]**。

**本次候选未能达到 1860 的目标。** 以点估计计，距第一阶段目标还差 2.88987 分，距第二阶段目标还差 22.88987 分。95% 置信区间的上界也低于 1860。不把小样本探索中观察到的 1860 档分数作为最终性能报告。

也不声称找到了全局最优策略。当前成果是获得了符合原始规则的可行策略、可复现的评估体系，以及经过验证的 1857.11 分基线。1880 能否达成不在本次实验的判定范围内。

## 2. 从源码确认的游戏定义

### 分数与终止

`score` 不是累计奖励，而是当前棋盘位置。初始值为 1，棋盘大小为 2898，阶段数为 75。评估目标是游戏结束时位置 `score` 的期望值。到达棋盘末端本身并不构成 `terminal` 条件。

实际的终止条件是 `diceUse >= 100 && !isDouble`。因此游戏并不是以 100 次行动结束。固定移动卡和下一阶段卡不消耗骰子，还存在由双倍带来的额外骰子。如果第 100 次付费骰子不是双倍，则该行动之后不能再使用卡牌。该行动的落点效果会先行处理。

当前没有双倍奖励时掷骰，付费次数加 1；若掷出相同点数，则生成一个奖励。已有奖励时掷出的骰子不增加付费次数，而是解除该奖励。这种情况下即使再次掷出相同点数，双倍也不会连锁。

### 移动与格子

普通骰子移动无法越过前方遇到的第一个 event 6 或 9 格。卡牌移动不经过这一普通移动的停止规则。event 4 跳跃会被连续解析，如果最终落点格是 event 2 且手牌有余量，则获得卡牌。

在提供的内核中，event 1、3、5 没有额外的状态变更行为。我们没有给棋盘数据中的事件编号附加其他游戏中通常的含义。

### 卡牌与牌堆

卡牌由 30 个 ID 组成，分为固定移动卡、对骰子点数和乘以倍数的卡、下一阶段卡三类。把 type/value 相同的卡按效果归并后是 22 种。实际的行动不是选择卡牌种类，而是选择当前手牌的 1-based 槽位。

手牌最多 5 张，抽牌是从当前 `deckMask` 中剩余的 ID 里均匀选择。已使用的卡牌不会立即回到牌堆。牌堆全部抽完后，会立即以全部 30 个 ID 重新生成。这一重新生成也包含当前手牌中的 ID，因此在不同的牌堆周期中可能重复持有相同 ID。所以不能把手牌当作简单的 ID 集合处理。

**源码依据：** `engine/board.js`、`engine/tables.js`、`rules/index.js`、`rules/card-data.js`、`rules/board-data.js`。随附原始文件的 SHA-256 记录在 `source-manifest.json` 中。

## 3. 问题的数学定义

将可观测状态定义如下。

```
s = (p, r, b, H, D)
p: 当前位置
r: 剩余付费骰子次数 = 100 - diceUse
b: 当前是否有双倍奖励
H: 允许重复的手牌
D: 当前剩余牌堆
```

行动集合为 `{0, 1, ..., cardCount}`。0 是普通骰子，其余是手牌槽位。策略不读取环境的随机数函数、种子或未来骰子值。前提是剩余牌堆可由当前状态或已观测的抽牌历史得知。在观测限制不同的环境中，需要单独的策略和评估。

目标是 `J(pi) = E_pi[p_terminal]`。终止状态的价值是当前位置，非终止状态的最优价值是各合法行动的下一状态价值期望中的最大值。也可以用移动量作为奖励，但那样必须不加折扣地求和才能与最终位置一致。我们没有在实际评估分数中加入任何折扣率或卡牌获取奖励。

假设两个均匀独立的六面骰，点数和为 d 的组合数是 `6 - |7-d|`。在没有奖励的状态下，偶数和恰好存在一个双倍组合，因此必须联合使用点数和与双倍的联合概率。我们没有采用把骰子点数和与是否双倍独立抽取的近似。

## 4. 选定的策略

### 4.1 辅助动态规划模型

我们没有原样存储全部真实状态空间，而是计算了一个辅助问题：手牌最多 4 张，抽牌采用全部 30 张分布的有放回抽取。规划 horizon 为 24 次付费骰子，奖励状态单独计算。原游戏的 5 张上限和无放回牌堆并未完全包含在这个辅助问题中。

按效果归并相同卡牌 ID 后为 22 种，最多 4 张手牌是允许重复的组合，共 14,950 个。由于不消耗骰子的卡牌使用和卡牌再获取会在同一资源 horizon 内产生依赖，因此采用迭代计算处理。实现的数值停止容差为 0.001。这并不是全局最优性的误差认证。

并不存储所有 horizon 的全部手牌价值，而是复用计算过程中所需的层。最终只保留各位置、剩余次数、奖励状态下空手牌、单张手牌、两手牌的 276 个值。由于辅助问题的概率模型与真实游戏不同，这些值不会被解读为真实游戏最优值的上界或下界。

### 4.2 真实手牌的近似价值

将空手牌价值记为 B，单张卡牌 c 的额外价值记为 U(c)，两张卡牌的额外交互记为 Delta(c,d)。

```
U(c)       = V({c}) - V(empty)
Delta(c,d) = V({c,d}) - V({c}) - V({d}) + V(empty)

V_hat(s) = B + 0.95 * sum U(c)
             + 0.95 * 0.75 * sum_{card pairs} Delta(c,d)
```

对真实的 3~5 张手牌也使用这个表达式。因此它并不是完整还原显式三重、四重、五重交互的模型。这是利用辅助模型的价值近似，剩余误差通过真实游戏模拟判断。最终的各卡牌种类额外权重和抽牌权重均为 1。

### 4.3 真实规则的两层期望值搜索

选定策略对应以下运算。

```
Q1(s,a) = E[V_hat(s') | s,a]
Q2(s,a) = E[max_a' Q1(s',a') | s,a]
pi(s)   = argmax_a Q2(s,a)
```

前两层的转移使用真实牌堆掩码、真实手牌、真实的双倍、终止和落点规则。骰子和抽牌结果不是抽取单个样本，而是按概率取平均。第二个行动根据观察到第一个结果后的状态来选择，并不是先看到未来的隐藏结果再选择行动的方式。

最终搜索不是蒙特卡洛采样策略，也不是 MCTS。它是对相同观测状态给出相同行动的确定性 expectimax 策略。当真实剩余次数大于 24 时，将价值表的规划窗口设为 24，并在搜索中一致地递减虚拟的剩余次数。由于价值表是近似值且窗口受限，两层期望值计算本身精确并不意味着整个策略最优。

## 5. 真实实验结果

固定候选、配置和模型后，执行了此前选择过程未使用的、起始种子为 1937719000 的 100,000 局测试库。每局的真实 PRNG 初始值为 `mix(baseSeed + episode)`。原始 CSV 的 `seed` 列是已应用该变换的初始值。

| 策略 | 局数 | 平均最终 score | 95% 置信区间 |
|---|---:|---:|---:|
| 仅使用普通骰子 | 100,000 | 943.68135 | 943.30783~944.05487 |
| 调参过的简单卡牌启发式 | 100,000 | 1784.97128 | 1783.77084~1786.17172 |
| 相同 DP4 价值模型，单层选择 | 100,000 | 1847.88476 | 1846.64634~1849.12318 |
| **DP4 + 两层期望值搜索** | **100,000** | **1857.11013** | **1855.85355~1858.36671** |

相对单层策略的平均差异为 **+9.22537 分**。将相同初始种子配对后的分数差异的 95% 置信区间为 **[7.86859, 10.58215]**。这一改进在最终样本中也得到了确认，但改进的幅度不足以越过 1860。

最终策略的中位数为 1856，下 10% 分位为 1593，上 10% 分位为 2120。最小值为 1023，最大值为 2724。平均行动数为 165.42222，最多 219 次。评估过程中没有对局触及安全行动上限或被排除。

单局得分达到 1860 以上的比例为 49.288%，达到 1880 以上的比例为 45.237%。这与平均期望 score 目标是否达成是不同的指标，未将其用作通过标准。

### 失败或未采纳的尝试

初期简单启发式在单独的 10,000 局中约 1482 分。通过调整卡牌获取价值和保留标准，得到了 1780 档的基线。依赖不精确终局价值的短蒙特卡洛 rollout 在某项配置的 1,000 局中反而恶化到 1668.32 分。基于这一结果，我们没有简单地增加样本数或搜索深度，而是改进了价值近似。

我们逐步比较了单卡近似、双卡模型、三卡辅助模型和四卡辅助模型。无条件加大规划窗口也不总是带来改进。我们没有只报告预备选择过程中的最高分，而是另行执行了最终固定评估。

选定候选在 1,000 局预备实验中记录 1862.79 分，在独立 10,000 局验证中记录 1859.3009 分，但在最终 100,000 局中为 1857.11013 分。这是必须区分候选选择与样本波动影响的直接例证。我们不把预备实验的 1862.79 分用作达成目标的依据。

## 6. 模拟器与部署策略验证

100,000 局主评估在 C++ 研究用模拟器中执行。这与原始 JavaScript 运行相区分。

- 独立的 JavaScript 参照实现与原始 Board：对照了 37,798 项表检查和 265,267 项真实状态转移。
- 在相同的随机行动执行下，C++ 与 JavaScript 的转移数 265,267 项及累计状态哈希 329317741 一致。
- 在原始 `Board.js` 中运行最终策略 1,024 局。每局的 score 和行动数与 C++ 全部一致。
- 最终 1,024 局的行动与分数序列累计哈希在两种语言中均为 3985191187。非法行动和直接修改游戏状态的检查均通过。

哈希一致并不是对所有可能状态的形式化等价证明，但它是针对引擎移植错误和策略不一致的实际验证依据。此外，五个原始游戏文件没有被修改。

在原始 JavaScript 中验证 1,024 局耗时 69.13 秒。该测量是在同时运行四个 C++ 评估的条件下进行的，不含加载时间，并且包含状态不变性检查等。不应将其解读为独立的部署延迟保证。

价值表原始大小为 160,024,804 字节，gzip 压缩模型为 96,560,579 字节。本次产出不包含面向浏览器的小型模型。在 Node.js 中无需外部包即可读取压缩模型并运行。

## 7. 缩小剩余差距的后续研究

### 优先级 A — 依赖牌堆条件的长期价值

最终搜索的前两层反映了当前牌堆，但价值表的长期抽牌是全牌堆有放回抽取的近似。合理的做法是先测量真实牌堆中倍数卡的剩余量、各卡牌效果的剩余量以及牌堆重新生成时机带来的长期价值误差。一个候选方案是在现有 DP4 之上叠加以各效果牌堆计数和手牌为输入的残差价值模型。

```
V_residual(s) = V_DP4(s) + f_theta(position, remainingDice, bonus, handCounts, deckCounts)
```

这还不是已实现、训练并验证的最终策略，而是下一阶段的实验设计。需要结合当前策略的真实轨迹、基于模型的 Bellman 目标和最终结果进行校正，并在独立种子上确认真实期望 score 是否改善。

### 优先级 B — 3~5 张交互与终局区间

当前部署的价值表示只显式使用到两张卡牌的交互。计划收集三卡联动重要的状态以及单层与两层策略选择分歧的状态，测量额外计算的价值。对于剩余付费骰子为 1~3 次的可达状态，实验包含真实牌堆的记忆化搜索和计算量限制。不能假设最后一个骰子之后还能使用卡牌。

### 优先级 C — 选择性深度搜索与模型轻量化

与其对所有状态施加相同的额外搜索，不如比较把计算集中到顶部候选行动价值差距小、或手牌联动多的状态上的方式。更深的搜索并不总是更好，因此需要按搜索深度、按终局价值做消融实验。

若要缩小部署体积，也可以考虑以精确搜索策略为教师进行策略或价值模型蒸馏。但不能仅凭压缩率或速度采纳，必须同时测量原有评估分数和边界情况下的行动一致性。

### 维护验证流程

把本次最终测试库再次用于训练或调参后，不得将同一个库称为新的独立最终测试。新候选要在新的种子库中以固定的样本数验证。第一阶段目标保持平均 1860、挑战目标 1880，并作为保守的通过标准，同时记录双侧 95% 置信区间下限是否不低于相应目标。
