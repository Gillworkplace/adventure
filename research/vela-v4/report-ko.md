## 3. 价值函数与两层搜索

使用位置 p、剩余付费骰子 r、对子奖励 b、手牌 H 和剩余牌堆 D。
原始游戏的付费骰子上限始终为 100，手牌为 5 张，抽牌为不放回抽取。
仅策略内部的规划窗口以 `min(实际剩余付费骰子, 24)` 加以限制。

设 A4 为把四张辅助问题的空手牌、单卡、双卡价值投影得到的函数，则

```text
A4(r,b,p,H) = B4 + 0.975 * (sum(U4) + 0.75 * sum(pairInteraction4))
alpha(r,b) = min(1, (r+b)/12)
Vhat(s) = A4(r,b,p,H)
        + alpha(r,b) * (F5(24,b,p,H) - A4(24,b,p,H))
        + DeckPotential(D,r,b)
```

其中 F5 是保留下来的五张完整手牌价值。`alpha` 是一个缩减系数，用于避免在临近终局时把长剩余资源下的手牌修正原样照搬。
在 horizon 24 处，叠加牌堆修正之前的值与存储的 F5 值一致。在其他 horizon 处，它并不是精确的五张 DP 值，而是经时间修正的近似。

牌堆修正沿用了既有的中心化卡片系数 a_i。

```text
DeckPotential = 0.6 * min(1, 0.7*(r+b)/deckCount) * sum(a_i for i in deck)
```

发生抽牌时，既反映去掉所抽卡片后的牌堆，也反映最后一张牌触发的牌堆重生成。终止状态的值就是位置本身，不额外叠加手牌或牌堆价值。

行动选择采用两层期望值搜索。

```text
Q1(s,a) = E[Vhat(s') | s,a]
Q2(s,a) = E[max_a' Q1(s',a') | s,a]
policy(s) = argmax_a Q2(s,a)
```

前两个行动的骰子点数之和与对子、卡片移除、跳跃、抵达事件、不放回抽牌与牌堆重生成均按原始规则处理。
但在此之后的价值中，仍保留了辅助模型的 IID 抽牌与有限规划窗口近似。
策略只接收当前公开状态，不接收未来随机数或游戏种子。

## 6. 此前终局阶段草案的实际实现与验证

实现了独立的 C++ 终局搜索器和 JavaScript 连接模块。
它将最终 score 的真实期望值一直计算到终局，并保持当前牌堆的不放回抽取。
只有在把当前状态的所有行动及概率分支完整计算到底时才采纳该行动，超出预算则回退到既有 agent。

只缓存已算完的状态，游戏过程中不清空缓存。
已算完状态的所有可能非终止后继状态也均已计算，因此即使缓存占满，仍可查询这些后续行动。
在假设实数运算精确且转移正确的前提下，这种在已算完状态持续采取最优行动的切换不会降低基准策略的期望值。
以上说明并不是声称对浮点误差也做了形式化认证。

### 64 位状态键

相同 type/value 的卡片按效果归并。其中 8 种各有两张、14 种各有一张，因此牌堆余量空间为 `3^8 * 2^14 = 107,495,424`。
状态键的位布局如下。

```text
位置 12 位 + 剩余付费骰子 7 位 + 奖励 1 位
+ 手牌排名 17 位 + 按效果的牌堆编码 27 位 = 64 位
```

对 80,730 个手牌的排名与键冲突做了全量检查。还对 100,000 个随机牌堆的按效果余量共 2,200,000 项进行了比对。
该表示保持了按效果的转移概率。这并不意味着让不同原始 ID 以相同随机数被抽中的序列本身也保持一致。
实际行动会还原到具有该效果的原始手牌槽位上。

### 终局模块的效果很小

在相同的 500 局开发样本上，H48 为 1867.044 分，附加剩余 1 次终局搜索的候选为 1867.194 分。
配对差异为 +0.15 分，95% 置信区间约为 -0.084~+0.384 分。仅凭样本无法确证存在正向改进。
使用剩余 2 次和更大的搜索预算，得到的分数序列也相同。
扩展状态数从 4,937,936 个增加到 67,124,588 个，但该样本的最终分数没有进一步改善。

因此没有把该模块作为突破 1880 的主要依据。v4 主策略的最终性能与终局模块的开发实验是两回事。

## 8. 最终评估流程

最终种子库为 4070909000，第 i 个种子为 `mix(4070909000 + i)`。
50,000 局的样本数与选定策略在运行前已固定。四个评估进程运行互不相同的游戏，每局游戏保持独立的随机数流。
策略设置、评估可执行文件哈希、种子及样本数记录在 `results/final-evaluation-plan.json` 与各评估文件夹的 `plan.json` 中。
运行过程中没有根据分数更改策略或样本数。

H48 对照组在新种子库的前 10,000 个种子上运行。与 v3 的比较则是对既有附件 CSV 的重新汇总。
平均值与配对差异的置信区间均由按游戏计的标准误乘以 1.96 得到。
与不同种子库的 v3 之间的差异则使用两个样本平均值的方差和。

整局游戏行动数的安全上限为 1040。由于默认初始手牌为空且奖励不会连锁，最大掷骰次数为 200 次。
设完全耗尽的牌堆次数为 C，倍数卡的使用次数为 U，则有 `6C <= U+5 <= 205`，因此 C 至多为 34。
免费卡在已耗尽的牌堆与最后一个未耗尽的牌堆中最多有 `24(C+1) <= 840` 张。因此行动数不超过 200+840。
这是一个保守上限，并不意味着求出了实际可行的最紧最大值。

## 9. 运行资料与剩余课题

运行方法参见 `README_KO.md`。完整运行包包含所需的三个压缩模型。
模型还原是检查点解码与四张模型解压，并不是从头重新计算庞大的 DP。
终局搜索可通过 `agent/endgame-wrapper.mjs` 单独接入既有策略。

目前未验证的部分包括：包含真实不放回牌堆的长期价值、五张 horizon 25 及以上的策略效果，以及全局最优值。
考虑到终局阶段实验的改进量很小，下一个有价值的研究方向是剩余牌堆较小时区间的条件搜索，以及长期价值误差。
不预先以数值保证其效果或能否达到 1880。
